166/*
167 ZCL8 specification, subsection 11.4.2.7, has done recommendations about versioning (at least to
168 divide version to 4 parts - Stack Build, Stack Release, Application Build and Application
169 Release), but does not specify comparing method. Looks like we do not have any limitations and
170 may upgrade/downgrade any f/w (except re-installation), so this comparing is simply:
171 ver1 != ver2
172 Only one possible limitation now is NVRAM, but if dataset ids are not overlapped, it is also ok.
173 Any additional comparison logic may be implemented on the application level.
174 */
176#define ZB_ZCL_OTA_UPGRADE_VERSION_CMP(ver1, ver2) \
177 ( (ver1) != (ver2) )
