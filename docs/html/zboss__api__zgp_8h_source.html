461/*
462 Using of Mapping Table.
463
464 Mapping table functionality is ZBOSS custom implementation of Translation table, described in specification.
465 Currently ZBOSS handles GPD commands mapping, which MAY be placed in mapping table, provided by application.
466
467 Mapping Table is a specific mapping rules declared in the application.
468 The specific mapping supersedes the generic one.
469
470 The application MAY or MAY not to declare Mapping Table.
471 If application declares Mapping Table it SHOULD persist this data by its own.
472
473 Mapping Table entries SHALL be added upon successful completion of proximity and multi-hop commissioning,
474 and upon reception of GP Pairing Configuration leading to Sink Table entry creation (as described in A.3.5.2.5);
475 those entries SHALL then contain the ApplicationID and GPD ID type and value of the GPD ID (and GPD Endpoint,
476 matching or 0x00 or 0xff, if ApplicationID = 0b010) for which they are created;
477 mapping the GPD commands to their ZCL equivalents.
478
479 Supported features:
480
481 - There SHOULD be only one entry in the GPD Command Mapping Table for each
482 (GPD ID, GPD Endpoint, GPD Command, EndPoint, Zigbee Profile, Zigbee Cluster) tuple.
483 - For a single GPD ID (and GPD Endpoint, if ApplicationID = 0b010), there MAY be multiple
484 entries, e.g. for multiple GPD commands.
485 - For a single GPD ID (and GPD Endpoint, if ApplicationID = 0b010),
486 the same GPD Command could result in different mapped Zigbee CommandIDs,
487 for different EndPoint, Profile and Cluster values.
488 - For a single GPD ID, if ApplicationID = 0b010, there MAY be multiple entries,
489 for multiple GPD Endpoints, even for identical GPD commands.
490
491 GPD Command:
492 - If the GPD Command field is set to 0xAF, all of the following GPD sensor report commands: 0xA0 - 0xA3 are supported.
493 - If the GPD Command field is set to 0xFF, it indicates all GPD commands.
494
495 Zigbee Endpoint:
496 - If the EndPoint field is set to 0xfd, there are no paired endpoints.
497 - If the EndPoint field is set to 0xff, all matching endpoints are paired.
498 - If the EndPoint field is set to 0xfc, the raw GPD command is passed up to the application,
499 and no mapping is performed in the GPEP.
500
501 Zigbee Cluster:
502 - If the Zigbee Cluster field is set to 0xffff, the ClusterID from the triggering GPD command is to be used.
503 - If the Zigbee Cluster field is set to value other than 0xffff, then for GPD command carrying
504 a ClusterID field (as e.g. for the GPD commands 0xA0 - 0xA3), the two ClusterID values SHALL exactly match.
505
506 ZCL Payload Length:
507 - If the Length sub-field of the Zigbee Command payload field is set to 0x00,
508 the Payload sub-field is not present, and the Zigbee command is sent without payload.
509 - If the Length sub-field of the Zigbee Command payload field is set to 0xff,
510 the Payload sub-field is not present, and the payload from the triggering GPD command
511 is to be copied verbatim into the Zigbee command.
512 - If the Length sub-field of the Zigbee Command payload field is set to 0xfe,
513 the Payload sub-field is not present, and the payload from the triggering GPD command needs to be parsed.
514 - For all other values of the Length sub-field, the Payload sub-field is present,
515 has a length as defined in the Length sub-field and specifies the payload to be used.
516
517 Not supported features:
518 - The Additional information block field is not supported yet.
519 */
