The ALPN extension (\href{https://tools.ietf.org/html/rfc7301}{\texttt{ RFC 7301}}) allows the client to send a list of application protocol names, and the server to select one. A mismatch is one of the following occurrences\+:


\begin{DoxyItemize}

Get the current engine state. 

An SSL engine (client or server) has, at any time, a state which is the combination of zero, one or more of these flags\+:


\begin{DoxyItemize}
\item {\ttfamily BR\+\_\+\+SSL\+\_\+\+CLOSED}

Engine is finished, no more I/O (until next reset).
\item {\ttfamily BR\+\_\+\+SSL\+\_\+\+SENDREC}

Engine has some bytes to send to the peer.
\item {\ttfamily BR\+\_\+\+SSL\+\_\+\+RECVREC}

Engine expects some bytes from the peer.
\item {\ttfamily BR\+\_\+\+SSL\+\_\+\+SENDAPP}

Engine may receive application data to send (or flush).
\item {\ttfamily BR\+\_\+\+SSL\+\_\+\+RECVAPP}

Engine has obtained some application data from the peer, that should be read by the caller.
\end{DoxyItemize}

If no flag at all is set (state value is 0), then the engine is not fully initialised yet.

The {\ttfamily BR\+\_\+\+SSL\+\_\+\+CLOSED} flag is exclusive; when it is set, no other flag is set. To distinguish between a normal closure and an error, use {\ttfamily br\+\_\+ssl\+\_\+engine\+\_\+last\+\_\+error()}.

Export key material from a connected SSL engine (RFC 5705). 

This calls compute a secret key of arbitrary length from the master secret of a connected SSL engine. If the provided context is not currently in "{}application data"{} state (initial handshake is not finished, another handshake is ongoing, or the connection failed or was closed), then this function returns 0. Otherwise, a secret key of length {\ttfamily len} bytes is computed and written in the buffer pointed to by {\ttfamily dst}, and 1 is returned.

The computed key follows the specification described in RFC 5705. That RFC includes two key computations, with and without a "{}context value"{}. If {\ttfamily context} is {\ttfamily NULL}, then the variant without context is used; otherwise, the {\ttfamily context\+\_\+len} bytes located at the address pointed to by {\ttfamily context} are used in the computation. Note that it is possible to have a "{}with context"{} key with a context length of zero bytes, by setting {\ttfamily context} to a non-\/{\ttfamily NULL} value but {\ttfamily context\+\_\+len} to 0.

When context bytes are used, the context length MUST NOT exceed 65535 bytes.

Initialise a simplified I/O wrapper context. 

The simplified I/O wrapper offers a simpler read/write API for a SSL engine (client or server), using the provided callback functions for reading data from, or writing data to, the transport medium.

The callback functions have the following semantics\+:


\begin{DoxyItemize}
\item Each callback receives an opaque context value (of type {\ttfamily void \texorpdfstring{$\ast$}{*}}) that the callback may use arbitrarily (or possibly ignore).
\item {\ttfamily low\+\_\+read()} reads at least one byte, at most {\ttfamily len} bytes, from the transport medium. Read bytes shall be written in {\ttfamily data}.
\item {\ttfamily low\+\_\+write()} writes at least one byte, at most {\ttfamily len} bytes, unto the transport medium. The bytes to write are read from {\ttfamily data}.
\item The {\ttfamily len} parameter is never zero, and is always lower than 20000.
\item The number of processed bytes (read or written) is returned. Since that number is less than 20000, it always fits on an {\ttfamily int}.
\item On error, the callbacks return -\/1. Reaching end-\/of-\/stream is an error. Errors are permanent\+: the SSL connection is terminated.
\item Callbacks SHOULD NOT return 0. This is tolerated, as long as callbacks endeavour to block for some non-\/negligible amount of time until at least one byte can be sent or received (if a callback returns 0, then the wrapper invokes it again immediately).
\item Callbacks MAY return as soon as at least one byte is processed; they MAY also insist on reading or writing {\itshape all} requested bytes. Since SSL is a self-\/terminated protocol (each record has a length header), this does not change semantics.
\item Callbacks need not apply any buffering (for performance) since SSL itself uses buffers.
\end{DoxyItemize}
