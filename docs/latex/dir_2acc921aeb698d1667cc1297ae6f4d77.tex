\doxysubsection{Detailed Description}
\hypertarget{README.md_autotoc_md1090}{}\doxysubsection{\texorpdfstring{Overview}{Overview}}\label{README.md_autotoc_md1090}
Serial flasher component provides portable library for flashing or loading ram loadble app to Espressif So\+Cs from other host microcontroller. Espressif So\+Cs are normally programmed via serial interface (UART). Port layer for given host microcontroller has to be implemented, if not available. Details can be found in section below.

Supported {\bfseries{host}} microcontrollers\+:


\begin{DoxyItemize}
\item STM32
\item Raspberry Pi
\item ESP32
\item MCU running Zephyr OS
\end{DoxyItemize}

Supported {\bfseries{target}} microcontrollers\+:


\begin{DoxyItemize}
\item ESP32
\item ESP8266
\item ESP32-\/\+S2
\item ESP32-\/\+S3
\item ESP32-\/\+C3
\item ESP32-\/\+C2
\item ESP32-\/\+H2
\end{DoxyItemize}\hypertarget{README.md_autotoc_md1091}{}\doxysubsection{\texorpdfstring{Supporting new host target}{Supporting new host target}}\label{README.md_autotoc_md1091}
In order to support new target, following function has to be implemented by user\+:


\begin{DoxyItemize}
\item loader\+\_\+port\+\_\+read()
\item loader\+\_\+port\+\_\+write()
\item loader\+\_\+port\+\_\+enter\+\_\+bootloader()
\item loader\+\_\+port\+\_\+delay\+\_\+ms()
\item loader\+\_\+port\+\_\+start\+\_\+timer()
\item loader\+\_\+port\+\_\+remaining\+\_\+time()
\end{DoxyItemize}

Following functions are part of io.\+h header for convenience, however, user does not have to strictly follow function signatures, as there are not called directly from library.


\begin{DoxyItemize}
\item loader\+\_\+port\+\_\+change\+\_\+transmission\+\_\+rate()
\item loader\+\_\+port\+\_\+reset\+\_\+target()
\item loader\+\_\+port\+\_\+debug\+\_\+print()
\end{DoxyItemize}

Prototypes of all function mentioned above can be found in \href{include/io.h}{\texttt{ io.\+h}}. Please refer to ports in {\ttfamily port} directory. Currently, ports for \href{port/esp32_port.c}{\texttt{ ESP32}}, \href{port/stm32_port.c}{\texttt{ STM32}}, and \href{port/zephyr_port.c}{\texttt{ Zephyr}} are available.\hypertarget{README.md_autotoc_md1092}{}\doxysubsection{\texorpdfstring{Configuration}{Configuration}}\label{README.md_autotoc_md1092}
These are the configuration toggles available to the user\+:
\begin{DoxyItemize}
\item MD5\+\_\+\+ENABLED
\end{DoxyItemize}

If enabled, serial flasher is capable of verifying flash integrity after writing to memory.

Default\+: Enabled \begin{quote}
Warning\+: As ROM bootloader of ESP8266 does not support MD5\+\_\+\+CHECK, this option has to be disabled! \end{quote}



\begin{DoxyItemize}
\item SERIAL\+\_\+\+FLASHER\+\_\+\+RESET\+\_\+\+HOLD\+\_\+\+TIME\+\_\+\+MS
\end{DoxyItemize}

This is the time for which the reset pin is asserted when doing a hard reset in milliseconds.

Default\+: 100


\begin{DoxyItemize}
\item SERIAL\+\_\+\+FLASHER\+\_\+\+BOOT\+\_\+\+HOLD\+\_\+\+TIME\+\_\+\+MS
\end{DoxyItemize}

This is the time for which the boot pin is asserted when doing a hard reset in milliseconds.

Default\+: 50

\hypertarget{README.md_autotoc_md1093}{}\doxysubsubsection{\texorpdfstring{STM32 support}{STM32 support}}\label{README.md_autotoc_md1093}
STM32 port make use of STM32 HAL libraries, that does not come with CMake support. In order to compile the project, {\ttfamily stm32-\/cmake} ({\ttfamily cmake} support package) has to be pulled as submodule.


\begin{DoxyCode}{0}
\DoxyCodeLine{git\ clone\ -\/-\/recursive\ https://github.com/espressif/esp-\/serial-\/flasher.git}

\end{DoxyCode}


If you have cloned this repository without the {\ttfamily -\/-\/recursive} flag, you can initialize the submodule using the following command\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{git\ submodule\ update\ -\/-\/init}

\end{DoxyCode}


In addition to configuration parameters mentioned above, following definitions has to be set\+:


\begin{DoxyItemize}
\item TOOLCHAIN\+\_\+\+PREFIX\+: path to arm toolchain (i.\+e /home/user/gcc-\/arm-\/none-\/eabi-\/9-\/2019-\/q4-\/major)
\item STM32\+Cube\+\_\+\+DIR\+: path to STM32 Cube libraries (i.\+e /home/user/\+STM32\+Cube/\+Repository/\+STM32\+Cube\+\_\+\+FW\+\_\+\+F4\+\_\+\+V1.25.\+0)
\item STM32\+\_\+\+CHIP\+: name of STM32 for which project should be compiled (i.\+e STM32\+F407\+VG)
\item PORT\+: STM32
\end{DoxyItemize}

This can be achieved by passing definition to command line, such as\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{cmake\ -\/DTOOLCHAIN\_PREFIX="{}/path\_to\_toolchain"{}\ -\/DSTM32Cube\_DIR="{}path\_to\_stm32Cube"{}\ -\/DSTM32\_CHIP="{}STM32F407VG"{}\ -\/DPORT="{}STM32"{}\ ..\ \&\&\ cmake\ -\/-\/build\ .}

\end{DoxyCode}


Alternatively, set those variables in top level {\ttfamily cmake} directory\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{set(TOOLCHAIN\_PREFIX\ \ \ \ path\_to\_toolchain)}
\DoxyCodeLine{set(STM32Cube\_DIR\ \ \ \ \ \ \ path\_to\_stm32\_HAL)}
\DoxyCodeLine{set(STM32\_CHIP\ \ \ \ \ \ \ \ \ \ STM32F407VG)}
\DoxyCodeLine{set(PORT\ \ \ \ \ \ \ \ \ \ \ \ \ \ \ \ STM32)}

\end{DoxyCode}
