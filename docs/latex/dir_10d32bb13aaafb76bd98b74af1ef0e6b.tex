\doxysubsection{Detailed Description}
This example demonstrates the basic usage of Free\+RTOS Semaphores and queue sets for coordination between tasks for multi-\/threading. Please refer to other examples in this folder to better understand the usage of tasks. It is also advised to read the documentation on Free\+RTOS web pages\+: \href{https://www.freertos.org/a00106.html}{\texttt{ https\+://www.\+freertos.\+org/a00106.\+html}}\hypertarget{README.md_autotoc_md422}{}\doxysubsubsection{\texorpdfstring{Theory\+:}{Theory\+:}}\label{README.md_autotoc_md422}
Semaphore is in essence a variable. Tasks can set the value, wait until one or more semaphores are set and thus communicate between each other their state. A binary semaphore is a semaphore that has a maximum count of 1, hence the \textquotesingle{}binary\textquotesingle{} name. A task can only \textquotesingle{}take\textquotesingle{} the semaphore if it is available, and the semaphore is only available if its count is 1.

Semaphores can be controlled by any number of tasks. If you use semaphore as a one-\/way signalization with only one task giving and only one task taking there is a much faster option called Task Notifications -\/ please see Free\+RTOS documentation and read more about them\+: \href{https://www.freertos.org/RTOS-task-notifications.html}{\texttt{ https\+://www.\+freertos.\+org/\+RTOS-\/task-\/notifications.\+html}}

This example uses a semaphore to signal when a package is delivered to a warehouse by multiple delivery trucks, and multiple workers are waiting to receive the package.\hypertarget{README.md_autotoc_md423}{}\doxysubsection{\texorpdfstring{Supported Targets}{Supported Targets}}\label{README.md_autotoc_md423}
This example supports all ESP32 So\+Cs.\hypertarget{README.md_autotoc_md424}{}\doxysubsubsection{\texorpdfstring{How to Use Example}{How to Use Example}}\label{README.md_autotoc_md424}
Read the code and try to understand it, then flash and observe the Serial output.
