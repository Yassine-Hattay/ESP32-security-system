Hash function or algorithm for signing the Server\+Key\+Exchange. 

This parameter is ignored for {\ttfamily TLS\+\_\+\+RSA\+\_\+\texorpdfstring{$\ast$}{*}} and {\ttfamily TLS\+\_\+\+ECDH\+\_\+\texorpdfstring{$\ast$}{*}} cipher suites; it is used only for {\ttfamily TLS\+\_\+\+ECDHE\+\_\+\texorpdfstring{$\ast$}{*}} suites, in which the server {\itshape signs} the ephemeral EC Diffie-\/\+Hellman parameters sent to the client.

This identifier must be one of the following values\+:


\begin{DoxyItemize}
\item {\ttfamily 0x\+FF00 + id}, where {\ttfamily id} is a hash function identifier (0 for MD5+\+SHA-\/1, or 2 to 6 for one of the SHA functions);
\item a full 16-\/bit identifier, lower than {\ttfamily 0x\+FF00}.
\end{DoxyItemize}

If the first option is used, then the SSL engine will compute the hash of the data that is to be signed, with the designated hash function. The {\ttfamily do\+\_\+sign()} method will be invoked with that hash value provided in the the {\ttfamily data} buffer.

If the second option is used, then the SSL engine will NOT compute a hash on the data; instead, it will provide the to-\/be-\/signed data itself in {\ttfamily data}, i.\+e. the concatenation of the client random, server random, and encoded ECDH parameters. Furthermore, with TLS-\/1.\+2 and later, the 16-\/bit identifier will be used "{}as is"{} in the protocol, in the Signature\+And\+Hash\+Algorithm; for instance, {\ttfamily 0x0401} stands for RSA PKCS\#1 v1.\+5 signature (the {\ttfamily 01}) with SHA-\/256 as hash function (the {\ttfamily 04}).

Take care that with TLS 1.\+0 and 1.\+1, the hash function is constrainted by the protocol\+: RSA signature must use MD5+\+SHA-\/1 (so use {\ttfamily 0x\+FF00}), while ECDSA must use SHA-\/1 ({\ttfamily 0x\+FF02}). Since TLS 1.\+0 and 1.\+1 don\textquotesingle{}t include a Signature\+And\+Hash\+Algorithm field in their Server\+Key\+Exchange messages, any value below {\ttfamily 0x\+FF00} will be usable to send the raw Server\+Key\+Exchange data to the {\ttfamily do\+\_\+sign()} callback, but that callback must still follow the protocol requirements when generating the signature. \Hypertarget{structbr__ssl__server__choices_af5e959f897bd948236647995a262ac34}\index{br\_ssl\_server\_choices@{br\_ssl\_server\_choices}!chain@{chain}}
