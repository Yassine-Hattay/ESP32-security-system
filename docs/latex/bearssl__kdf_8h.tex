\doxysubsection{Detailed Description}
\hypertarget{bearssl__kdf_8h_autotoc_md94}{}\doxysubsection{\texorpdfstring{Key Derivation Functions}{Key Derivation Functions}}\label{bearssl__kdf_8h_autotoc_md94}
KDF are functions that takes a variable length input, and provide a variable length output, meant to be used to derive subkeys from a master key.\hypertarget{bearssl__kdf_8h_autotoc_md95}{}\doxysubsubsection{\texorpdfstring{HKDF}{HKDF}}\label{bearssl__kdf_8h_autotoc_md95}
HKDF is a KDF defined by \href{https://tools.ietf.org/html/rfc5869}{\texttt{ RFC 5869}}. It is based on HMAC, itself using an underlying hash function. Any hash function can be used, as long as it is compatible with the rules for the HMAC implementation (i.\+e. output size is 64 bytes or less, hash internal state size is 64 bytes or less, and the internal block length is a power of 2 between 16 and 256 bytes). HKDF has two phases\+:


\begin{DoxyItemize}
\item HKDF-\/\+Extract\+: the input data in ingested, along with a "{}salt"{} value.
\item HKDF-\/\+Expand\+: the output is produced, from the result of processing the input and salt, and using an extra non-\/secret parameter called "{}info"{}.
\end{DoxyItemize}

The "{}salt"{} and "{}info"{} strings are non-\/secret and can be empty. Their role is normally to bind the input and output, respectively, to conventional identifiers that qualifu them within the used protocol or application.

The implementation defined in this file uses the following functions\+:


\begin{DoxyItemize}
\item {\ttfamily \doxylink{bearssl__kdf_8h_a8f4b7b14cb6ed21bbc928274a07c507c}{br\+\_\+hkdf\+\_\+init()}}\+: initialize an HKDF context, with a hash function, and the salt. This starts the HKDF-\/\+Extract process.
\item {\ttfamily \doxylink{bearssl__kdf_8h_a0b4b3f369fd8d3d3cde877379b5794c2}{br\+\_\+hkdf\+\_\+inject()}}\+: inject more input bytes. This function may be called repeatedly if the input data is provided by chunks.
\item {\ttfamily \doxylink{bearssl__kdf_8h_a29a7e227a467ffc451617415b744487f}{br\+\_\+hkdf\+\_\+flip()}}\+: end the HKDF-\/\+Extract process, and start the HKDF-\/\+Expand process.
\item {\ttfamily \doxylink{bearssl__kdf_8h_a6964c5ae43048a62d62796e871a0348e}{br\+\_\+hkdf\+\_\+produce()}}\+: get the next bytes of output. This function may be called several times to obtain the full output by chunks. For correct HKDF processing, the same "{}info"{} string must be provided for each call.
\end{DoxyItemize}

Note that the HKDF total output size (the number of bytes that HKDF-\/\+Expand is willing to produce) is limited\+: if the hash output size is {\itshape n} bytes, then the maximum output size is {\itshape 255\texorpdfstring{$\ast$}{*}n}.\hypertarget{bearssl__kdf_8h_autotoc_md96}{}\doxysubsubsection{\texorpdfstring{SHAKE}{SHAKE}}\label{bearssl__kdf_8h_autotoc_md96}
SHAKE is defined in \href{https://csrc.nist.gov/publications/detail/fips/202/final}{\texttt{ FIPS 202}} under two versions\+: SHAKE128 and SHAKE256, offering an alleged "{}security level"{} of 128 and 256 bits, respectively (SHAKE128 is about 20 to 25\% faster than SHAKE256). SHAKE internally relies on the Keccak family of sponge functions, not on any externally provided hash function. Contrary to HKDF, SHAKE does not have a concept of either a "{}salt"{} or an "{}info"{} string. The API consists in four functions\+:


\begin{DoxyItemize}
\item {\ttfamily \doxylink{bearssl__kdf_8h_a34d25fed6c642355aa283099c93c305b}{br\+\_\+shake\+\_\+init()}}\+: initialize a SHAKE context for a given security level.
\item {\ttfamily \doxylink{bearssl__kdf_8h_aa3908628dd2d12dba5301f054a5adf2d}{br\+\_\+shake\+\_\+inject()}}\+: inject more input bytes. This function may be called repeatedly if the input data is provided by chunks.
\item {\ttfamily \doxylink{bearssl__kdf_8h_ac4b15d31dc3e2e53470779289e06655c}{br\+\_\+shake\+\_\+flip()}}\+: end the data injection process, and start the data production process.
\item {\ttfamily \doxylink{bearssl__kdf_8h_af2fd4205a33d1f26323a2475d6b77269}{br\+\_\+shake\+\_\+produce()}}\+: get the next bytes of output. This function may be called several times to obtain the full output by chunks. 
\end{DoxyItemize}

HKDF context initialization. 

The underlying hash function and salt value are provided. Arbitrary salt lengths can be used.

HKDF makes a difference between a salt of length zero, and an absent salt (the latter being equivalent to a salt consisting of bytes of value zero, of the same length as the hash function output). If {\ttfamily salt\+\_\+len} is zero, then this function assumes that the salt is present but of length zero. To specify an {\itshape absent} salt, use {\ttfamily BR\+\_\+\+HKDF\+\_\+\+NO\+\_\+\+SALT} as {\ttfamily salt} parameter ({\ttfamily salt\+\_\+len} is then ignored).

SHAKE context initialization. 

The context is initialized for the provided "{}security level"{}. Internally, this sets the "{}capacity"{} to twice the security level; thus, for SHAKE128, the {\ttfamily security\+\_\+level} parameter should be 128, which corresponds to a 256-\/bit capacity.

Allowed security levels are all multiples of 32, from 32 to 768, inclusive. Larger security levels imply lower performance; levels beyond 256 bits don\textquotesingle{}t make much sense. Standard levels are 128 and 256 bits (for SHAKE128 and SHAKE256, respectively).
