Little\+FS for ESP-\/\+IDF.\hypertarget{README.md_autotoc_md1476}{}\doxysubsection{\texorpdfstring{What is Little\+FS?}{What is Little\+FS?}}\label{README.md_autotoc_md1476}
\href{https://github.com/ARMmbed/littlefs}{\texttt{ Little\+FS}} is a small fail-\/safe filesystem for microcontrollers. We ported Little\+FS to esp-\/idf (specifically, the ESP32) because SPIFFS was too slow, and FAT was too fragile.\hypertarget{README.md_autotoc_md1477}{}\doxysubsection{\texorpdfstring{How to Use}{How to Use}}\label{README.md_autotoc_md1477}

See the official \href{https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/storage/spiffs.html}{\texttt{ ESP-\/\+IDF SPIFFS documentation}}, basically all the functionality is the same; just replace {\ttfamily spiffs} with {\ttfamily littlefs} in all function calls.

Also see the comments in {\ttfamily \doxylink{esp__littlefs_8h_source}{include/esp\+\_\+littlefs.\+h}}

Slight differences between this configuration and SPIFFS\textquotesingle{}s configuration is in the {\ttfamily \doxylink{structesp__vfs__littlefs__conf__t}{esp\+\_\+vfs\+\_\+littlefs\+\_\+conf\+\_\+t}}\+:


\begin{DoxyEnumerate}
\item {\ttfamily max\+\_\+files} field doesn\textquotesingle{}t exist since we removed the file limit, thanks to @X-\/Ryl669
\item {\ttfamily partition\+\_\+label} is not allowed to be {\ttfamily NULL}. You must specify the partition name from your partition table. This is because there isn\textquotesingle{}t a define {\ttfamily littlefs} partition subtype in {\ttfamily esp-\/idf}. The subtype doesn\textquotesingle{}t matter.
\begin{DoxyItemize}
\item Alternatively, you can specify an {\ttfamily esp\+\_\+partition\+\_\+t\texorpdfstring{$\ast$}{*}} to a {\ttfamily partition} and set {\ttfamily partition\+\_\+label=NULL}.
\end{DoxyItemize}
\item {\ttfamily grow\+\_\+on\+\_\+mount} will expand an existing filesystem to fill the partition. Defaults to {\ttfamily false}.
\begin{DoxyItemize}
\item Little\+FS filesystems can only grow, they cannot shrink.
\end{DoxyItemize}
\end{DoxyEnumerate}\hypertarget{README.md_autotoc_md1482}{}\doxysubsubsubsection{\texorpdfstring{Filesystem Image Creation}{Filesystem Image Creation}}\label{README.md_autotoc_md1482}

\hypertarget{README.md_autotoc_md1488}{}\doxysubsection{\texorpdfstring{Tips, Tricks, and Gotchas}{Tips, Tricks, and Gotchas}}\label{README.md_autotoc_md1488}

\begin{DoxyItemize}
\item Little\+FS operates on blocks, and blocks have a size of 4096 bytes on the ESP32.
\item A freshly formatted Little\+FS will have 2 blocks in use, making it seem like 8KB are in use.
\item The esp32 has \href{https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/peripherals/spi_flash/spi_flash_concurrency.html\#concurrency-constraints-for-flash-on-spi1}{\texttt{ flash concurrency constraints}}. When using UART (either for data transfer or generic logging) at the same time, you {\itshape MUST} enable the following option in KConfig\+: {\ttfamily menuconfig \texorpdfstring{$>$}{>} Component config \texorpdfstring{$>$}{>} Driver config \texorpdfstring{$>$}{>} UART \texorpdfstring{$>$}{>} UART ISR in IRAM}.
\end{DoxyItemize}\hypertarget{README.md_autotoc_md1489}{}\doxysubsection{\texorpdfstring{Running Unit Tests}{Running Unit Tests}}\label{README.md_autotoc_md1489}
