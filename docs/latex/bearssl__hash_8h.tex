\doxysubsection{Detailed Description}
\hypertarget{bearssl__hash_8h_autotoc_md87}{}\doxysubsection{\texorpdfstring{Hash Functions}{Hash Functions}}\label{bearssl__hash_8h_autotoc_md87}
This file documents the API for hash functions.\hypertarget{bearssl__hash_8h_autotoc_md88}{}\doxysubsubsection{\texorpdfstring{Procedural API}{Procedural API}}\label{bearssl__hash_8h_autotoc_md88}
For each implemented hash function, of name "{}\`{}xxx\`{}"{}, the following elements are defined\+:


\begin{DoxyItemize}
\item {\ttfamily br\+\_\+xxx\+\_\+vtable}

An externally defined instance of {\ttfamily \doxylink{bearssl__hash_8h_ae38c1b9d539537cc16fc84388b922d86}{br\+\_\+hash\+\_\+class}}.
\item {\ttfamily br\+\_\+xxx\+\_\+\+SIZE}

A macro that evaluates to the output size (in bytes) of the hash function.
\item {\ttfamily br\+\_\+xxx\+\_\+\+ID}

A macro that evaluates to a symbolic identifier for the hash function. Such identifiers are used with HMAC and signature algorithm implementations.

NOTE\+: for the "{}standard"{} hash functions defined in \href{https://tools.ietf.org/html/rfc5246\#section-7.4.1.4.1}{\texttt{ the TLS standard}}, the symbolic identifiers match the constants used in TLS, i.\+e. 1 to 6 for MD5, SHA-\/1, SHA-\/224, SHA-\/256, SHA-\/384 and SHA-\/512, respectively.
\item {\ttfamily br\+\_\+xxx\+\_\+context}

Context for an ongoing computation. It is allocated by the caller, and a pointer to it is passed to all functions. A context contains no interior pointer, so it can be moved around and cloned (with a simple {\ttfamily memcpy()} or equivalent) in order to capture the function state at some point. Computations that use distinct context structures are independent of each other. The first field of {\ttfamily br\+\_\+xxx\+\_\+context} is always a pointer to the {\ttfamily br\+\_\+xxx\+\_\+vtable} structure; {\ttfamily br\+\_\+xxx\+\_\+init()} sets that pointer.
\item {\ttfamily br\+\_\+xxx\+\_\+init(br\+\_\+xxx\+\_\+context \texorpdfstring{$\ast$}{*}ctx)}

Initialise the provided context. Previous contents of the structure are ignored. This calls resets the context to the start of a new hash computation; it also sets the first field of the context structure (called {\ttfamily vtable}) to a pointer to the statically allocated constant {\ttfamily br\+\_\+xxx\+\_\+vtable} structure.
\item {\ttfamily br\+\_\+xxx\+\_\+update(br\+\_\+xxx\+\_\+context \texorpdfstring{$\ast$}{*}ctx, const void \texorpdfstring{$\ast$}{*}data, size\+\_\+t len)}

Add some more bytes to the hash computation represented by the provided context.
\item {\ttfamily br\+\_\+xxx\+\_\+out(const br\+\_\+xxx\+\_\+context \texorpdfstring{$\ast$}{*}ctx, void \texorpdfstring{$\ast$}{*}out)}

Complete the hash computation and write the result in the provided buffer. The output buffer MUST be large enough to accommodate the result. The context is NOT modified by this operation, so this function can be used to get a "{}partial hash"{} while still keeping the possibility of adding more bytes to the input.
\item {\ttfamily br\+\_\+xxx\+\_\+state(const br\+\_\+xxx\+\_\+context \texorpdfstring{$\ast$}{*}ctx, void \texorpdfstring{$\ast$}{*}out)}

Get a copy of the "{}current state"{} for the computation so far. For MD functions (MD5, SHA-\/1, SHA-\/2 family), this is the running state resulting from the processing of the last complete input block. Returned value is the current input length (in bytes).
\item {\ttfamily br\+\_\+xxx\+\_\+set\+\_\+state(br\+\_\+xxx\+\_\+context \texorpdfstring{$\ast$}{*}ctx, const void \texorpdfstring{$\ast$}{*}stb, uint64\+\_\+t count)}

Set the internal state to the provided values. The \textquotesingle{}stb\textquotesingle{} and \textquotesingle{}count\textquotesingle{} values shall match that which was obtained from {\ttfamily br\+\_\+xxx\+\_\+state()}. This restores the hash state only if the state values were at an appropriate block boundary. This does NOT set the {\ttfamily vtable} pointer in the context.
\end{DoxyItemize}

Context structures can be discarded without any explicit deallocation. Hash function implementations are purely software and don\textquotesingle{}t reserve any resources outside of the context structure itself.\hypertarget{bearssl__hash_8h_autotoc_md89}{}\doxysubsubsection{\texorpdfstring{Object-\/\+Oriented API}{Object-\/\+Oriented API}}\label{bearssl__hash_8h_autotoc_md89}
For each hash function that follows the procedural API described above, an object-\/oriented API is also provided. In that API, function pointers from the vtable ({\ttfamily br\+\_\+xxx\+\_\+vtable}) are used. The vtable incarnates object-\/oriented programming. An introduction on the OOP concept used here can be read on the Bear\+SSL Web site\+:~\newline
 ~~~\href{https://www.bearssl.org/oop.html}{\texttt{ https\+://www.\+bearssl.\+org/oop.\+html}}

The vtable offers functions called {\ttfamily init()}, {\ttfamily update()}, {\ttfamily out()}, {\ttfamily set()} and {\ttfamily set\+\_\+state()}, which are in fact the functions from the procedural API. That vtable also contains two informative fields\+:


\begin{DoxyItemize}
\item {\ttfamily context\+\_\+size}

The size of the context structure ({\ttfamily br\+\_\+xxx\+\_\+context}), in bytes. This can be used by generic implementations to perform dynamic context allocation.
\item {\ttfamily desc}

A "{}descriptor"{} field that encodes some information on the hash function\+: symbolic identifier, output size, state size, internal block size, details on the padding.
\end{DoxyItemize}

Users of this object-\/oriented API (in particular generic HMAC implementations) may make the following assumptions\+:


\begin{DoxyItemize}
\item Hash output size is no more than 64 bytes.
\item Hash internal state size is no more than 64 bytes.
\item Internal block size is a power of two, no less than 16 and no more than 256.
\end{DoxyItemize}\hypertarget{bearssl__hash_8h_autotoc_md90}{}\doxysubsubsection{\texorpdfstring{Implemented Hash Functions}{Implemented Hash Functions}}\label{bearssl__hash_8h_autotoc_md90}

It can be useful in implementing SSL 3.\+0, TLS 1.\+0 and TLS 1.\+1.)\hypertarget{bearssl__hash_8h_autotoc_md91}{}\doxysubsubsection{\texorpdfstring{Multi-\/\+Hasher}{Multi-\/\+Hasher}}\label{bearssl__hash_8h_autotoc_md91}
An aggregate hasher is provided, that can compute several standard hash functions in parallel. It uses {\ttfamily \doxylink{structbr__multihash__context}{br\+\_\+multihash\+\_\+context}} and a procedural API. It is configured with the implementations (the vtables) that it should use; it will then compute all these hash functions in parallel, on the same input. It is meant to be used in cases when the hash of an object will be used, but the exact hash function is not known yet (typically, streamed processing on X.\+509 certificates).

Only the standard hash functions (MD5, SHA-\/1, SHA-\/224, SHA-\/256, SHA-\/384 and SHA-\/512) are supported by the multi-\/hasher.\hypertarget{bearssl__hash_8h_autotoc_md92}{}\doxysubsubsection{\texorpdfstring{GHASH}{GHASH}}\label{bearssl__hash_8h_autotoc_md92}
GHASH is not a generic hash function; it is a {\itshape universal} hash function, which, as the name does not say, means that it CANNOT be used in most places where a hash function is needed. GHASH is used within the GCM encryption mode, to provide the checked integrity functionality.

A GHASH implementation is basically a function that uses the type defined in this file under the name {\ttfamily \doxylink{bearssl__hash_8h_a06b9d6420d8038e78efbb53fb4a26eae}{br\+\_\+ghash}}\+: \begin{DoxyVerb}typedef void (*br_ghash)(void *y, const void *h, const void *data, size_t len);
\end{DoxyVerb}


The {\ttfamily y} pointer refers to a 16-\/byte value which is used as input, and receives the output of the GHASH invocation. {\ttfamily h} is a 16-\/byte secret value (that serves as key). {\ttfamily data} and {\ttfamily len} define the input data.

Three GHASH implementations are provided, all constant-\/time, based on the use of integer multiplications with appropriate masking to cancel carry propagation.

Type for a GHASH implementation. 

GHASH is a sort of keyed hash meant to be used to implement GCM in combination with a block cipher (with 16-\/byte blocks).

The {\ttfamily y} array has length 16 bytes and is used for input and output; in a complete GHASH run, it starts with an all-\/zero value. {\ttfamily h} is a 16-\/byte value that serves as key (it is derived from the encryption key in GCM, using the block cipher). The data length ({\ttfamily len}) is expressed in bytes. The {\ttfamily y} array is updated.

If the data length is not a multiple of 16, then the data is implicitly padded with zeros up to the next multiple of 16. Thus, when using GHASH in GCM, this method may be called twice, for the associated data and for the ciphertext, respectively; the zero-\/padding implements exactly the GCM rules.
