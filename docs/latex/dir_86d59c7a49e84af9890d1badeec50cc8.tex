\doxysubsection{Detailed Description}
!\mbox{[}ESP Mail\mbox{]}(\href{https://raw.githubusercontent.com/mobizt/ESP-Mail-Client/master/media/images/esp-mail-client.svg}{\texttt{ https\+://raw.\+githubusercontent.\+com/mobizt/\+ESP-\/\+Mail-\/\+Client/master/media/images/esp-\/mail-\/client.\+svg}})

  \href{https://github.com/mobizt/ESP-Mail-Client/stargazers}{\texttt{ }} 

 

The comprehensive Arduino Email \doxylink{class_client}{Client} Library to send and read Email for Arduino devices.

This library was tested and works well with ESP32s, ESP8266s, SAMD21s and RP2040 Pico based modules.

The library supported external networking devices hat work with Arduino Clients e.\+g. Wi\+Fi\+Client, Ethernet\+Client, and GSMClient.

Minimum 200k flash space device is recommended for library installation and user code.

The minimum ram requirement is based on the applications (SMTP and IMAP). IMAP application may required up to 20k memory while SMTP application required much less memory.\hypertarget{README.md_autotoc_md31}{}\doxysubsubsection{\texorpdfstring{Table of Contents}{Table of Contents}}\label{README.md_autotoc_md31}

\item Supports sending Email with attachments.

\item Supports IMAP MIME data stream callback for external reader.
\item supports IMAP custom character decoding callback based on the character set.
\item Support full debuging.
\item Support on-\/board or native networking (Wi\+Fi and Ethernet) and external networking (Wi\+Fi, Ethernet and GSM) via external basic Wi\+Fi\+Client, Ethernet\+Client and GSMClient.

To check the Keep\+Alive status, use {\ttfamily \texorpdfstring{$<$}{<}\doxylink{class_s_m_t_p_session}{SMTPSession}\texorpdfstring{$>$}{>}.is\+Keep\+Alive} or {\ttfamily \texorpdfstring{$<$}{<}\doxylink{class_i_m_a_p_session}{IMAPSession}\texorpdfstring{$>$}{>}.is\+Keep\+Alive}.

For the TCP (Keep\+Alive) options, see \href{https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-guides/lwip.html\#tcp-options}{\texttt{ here}}.

You can check the server connecting status, by executing {\ttfamily \texorpdfstring{$<$}{<}\doxylink{class_s_m_t_p_session}{SMTPSession}\texorpdfstring{$>$}{>}.connected()} or {\ttfamily \texorpdfstring{$<$}{<}\doxylink{class_i_m_a_p_session}{IMAPSession}\texorpdfstring{$>$}{>}.connected()} which will return true when connection to the server is still alive.

The TCP Keep\+Alive was currently available in ESP32 unless in ESP8266, \href{https://github.com/esp8266/Arduino/pull/8940}{\texttt{ this ESP8266 PR \#8940}} should be merged in the \href{https://github.com/esp8266/Arduino/releases}{\texttt{ ESP8266 Arduino Core SDK}}, i.\+e., it will be supported in the ESP8266 core version newer than v3.\+1.\+2.

In ESP8266 core v3.\+1.\+2 and older, the error can be occurred when executing {\ttfamily \texorpdfstring{$<$}{<}\doxylink{class_s_m_t_p_session}{SMTPSession}\texorpdfstring{$>$}{>}.keep\+Alive} or {\ttfamily \texorpdfstring{$<$}{<}\doxylink{class_i_m_a_p_session}{IMAPSession}\texorpdfstring{$>$}{>}.is\+Keep\+Alive} because of object slicing.

The Arduino Pico is currently not support TCP Keep\+Alive until it\textquotesingle{}s implemented in Wi\+Fi\+Client\+Secure library as in ESP8266.

For External \doxylink{class_client}{Client}, this TCP Keep\+Alive option is not appliable and should be managed by external \doxylink{class_client}{Client} library.\hypertarget{README.md_autotoc_md63}{}\doxysubsubsubsection{\texorpdfstring{Use External Arduino Clients for External Networking Devices}{Use External Arduino Clients for External Networking Devices}}\label{README.md_autotoc_md63}
This library supports external netwoking devices e.\+g. Wi\+Fi modules, Ethernet modules and GSM modules that connected to the Arduino device via communication ports e.\+g. SPI and Serial, through the Arduino Clients (driver) for those networking devices e.\+g. Wi\+Fi\+Client, Ethernet\+Client and GSMClient.

Since v3.\+4.\+0, the Arduino Clients can be used with this library without additional external SSL \doxylink{class_client}{Client} required.

No additional setup needed, only pass the Arduino \doxylink{class_client}{Client} to the function {\ttfamily set\+Client} or pass the Tiny\+GSMClient and Tiny\+GSM modem to the function {\ttfamily set\+GSMClient} or pass the Ethernet client and mac address to the function {\ttfamily set\+Ethernet\+Client}.

Two callback functions are required (except for {\ttfamily set\+GSMClient} and {\ttfamily set\+Ethernet\+Client}) for network connection (with disconnection) and sending connecting status back to the Mail \doxylink{class_client}{Client}.

If device has on-\/board Wi\+Fi and supports native (SDK) Ethernet, these two native networks will be auto detectd and used.

If you don\textquotesingle{}t want to let {\ttfamily ESP Mail \doxylink{class_client}{Client}} library to use the native networking and use external networking devices using Arduino Clients instead, the following build flags or macros should be defined in {\ttfamily Custom\+\_\+\+ESP\+\_\+\+Mail\+\_\+\+FS.\+h}.
