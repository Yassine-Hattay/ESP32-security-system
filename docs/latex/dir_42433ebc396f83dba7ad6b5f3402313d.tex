\doxysubsection{Detailed Description}
{\ttfamily network\+\_\+provisioning} uses Google Protobuf for language, transport and architecture agnostic protocol communication. These proto files define the protocomm packet structure, separated across multiple files\+:
\begin{DoxyItemize}
\item network\+\_\+contants.\+proto -\/ Defines the various enums for indicating state of network (connected / disconnect / connecting), diconnect reasons, auth modes, etc.
\item network\+\_\+config.\+proto -\/ Defines network configuration structures and commands for setting Wi-\/\+Fi credentials (SSID, passphrase, BSSID) or Thread dataset, applying credentials and getting connection state.
\item network\+\_\+scan.\+proto -\/ Defines network scan commands and result structures
\item network\+\_\+ctrl.\+proto -\/ Defines network control commands(reset and re-\/provision) and result structures
\end{DoxyItemize}

Note \+: These proto files are not automatically compiled during the build process.\hypertarget{README.md_autotoc_md1464}{}\doxysubsection{\texorpdfstring{Compilation}{Compilation}}\label{README.md_autotoc_md1464}
Compilation requires protoc (Protobuf Compiler) and protoc-\/c (Protobuf C Compiler) installed. Since the generated files are to remain the same, as long as the proto files are not modified, therefore the generated files are already available under {\ttfamily components/network\+\_\+provisioning/proto-\/c} and {\ttfamily components/network\+\_\+provisioning/python} directories, and thus running cmake / make (and installing the Protobuf compilers) is optional.
