\doxysubsection{Detailed Description}
\hypertarget{README.md_autotoc_md1248}{}\doxysubsection{\texorpdfstring{Overview}{Overview}}\label{README.md_autotoc_md1248}
The aim of this test is to exercise the most commonly failing scenario, running OTA over PPPoS with https.

This project opens a data session, runs basic mqtt operations and initiates OTA update. It supports the following test configurations\+:
\begin{DoxyItemize}
\item Using a real modem device (default config)
\item Using VFS device (only to exercise VFS DTE)
\item Using network-\/only DCE (connecting directly to PPP server) -- needs some configuration
\end{DoxyItemize}\hypertarget{README.md_autotoc_md1249}{}\doxysubsubsection{\texorpdfstring{Configuring the PPP server}{Configuring the PPP server}}\label{README.md_autotoc_md1249}
You need to run these applications on your host machine\+:
\begin{DoxyItemize}
\item PPP server 
\begin{DoxyCode}{0}
\DoxyCodeLine{sudo\ pppd\ /dev/ttyUSB1\ 115200\ 192.168.11.1:192.168.11.2\ ms-\/dns\ 8.8.8.8\ modem\ local\ noauth\ debug\ nocrtscts\ nodetach\ +ipv6}

\end{DoxyCode}

\item MQTT broker\+: Running mosquitto in the default config is enough, configuring the broker\textquotesingle{}s URL to the local PPP address\+: {\ttfamily config.\+broker.\+address.\+uri = "{}mqtt\+://192.\+168.\+11.\+1"{};}
\item HTTP server\+: Need to support HTTP/1.\+1 (to support ranges). You can use the script {\ttfamily http\+\_\+server.\+py} and configure the OTA endpoint as {\ttfamily "{}https\+://192.\+168.\+11.\+1\+:1234/esp32.\+bin"{}}
\end{DoxyItemize}\hypertarget{README.md_autotoc_md1250}{}\doxysubsection{\texorpdfstring{Potential issues}{Potential issues}}\label{README.md_autotoc_md1250}
When running this test it is expected to experience some buffer overflows or connection interruption. The modem library should recover from these failure modes and continue and complete OTA update. These issues are expected, since UART ISR is deliberately not placed into IRAM in the test configuration to exhibit some minor communication glitches.
