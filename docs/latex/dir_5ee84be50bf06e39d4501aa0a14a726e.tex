\doxysubsection{Detailed Description}
The \doxylink{class_network_client_secure}{Network\+Client\+Secure} class implements support for secure connections using TLS (SSL). It inherits from \doxylink{class_network_client}{Network\+Client} and thus implements a superset of that class\textquotesingle{} interface. There are three ways to establish a secure connection using the \doxylink{class_network_client_secure}{Network\+Client\+Secure} class\+: using a root certificate authority (CA) cert, using a root CA cert plus a client cert and key, and using a pre-\/shared key (PSK).\hypertarget{README.md_autotoc_md456}{}\doxysubsection{\texorpdfstring{Using a root certificate authority cert}{Using a root certificate authority cert}}\label{README.md_autotoc_md456}
This method authenticates the server and negotiates an encrypted connection. It is the same functionality as implemented in your web browser when you connect to HTTPS sites.

If you are accessing your own server\+:
\begin{DoxyItemize}
\item Generate a root certificate for your own certificate authority
\item Generate a cert \& private key using your root certificate ("{}self-\/signed cert"{}) for your server
\end{DoxyItemize}

If you are accessing a public server\+:
\begin{DoxyItemize}
\item Obtain the cert of the public CA that signed that server\textquotesingle{}s cert Then\+:
\item In \doxylink{class_network_client_secure}{Network\+Client\+Secure} use set\+CACert (or the appropriate connect method) to set the root cert of your CA or of the public CA
\item When \doxylink{class_network_client_secure}{Network\+Client\+Secure} connects to the target server it uses the CA cert to verify the certificate presented by the server, and then negotiates encryption for the connection
\end{DoxyItemize}

Please see the \doxylink{class_network_client_secure}{Network\+Client\+Secure} example.\hypertarget{README.md_autotoc_md457}{}\doxysubsection{\texorpdfstring{Using a bundle of root certificate authority certificates}{Using a bundle of root certificate authority certificates}}\label{README.md_autotoc_md457}
This method is similar to the single root certificate verification above, but it uses a standard set of root certificates from Mozilla to authenticate against, while the previous method only accepts a single certificate for a given server. This allows the client to connect to all public SSL servers.

\end{DoxyItemize}\hypertarget{README.md_autotoc_md459}{}\doxysubsection{\texorpdfstring{Using Pre-\/\+Shared Keys (PSK)}{Using Pre-\/\+Shared Keys (PSK)}}\label{README.md_autotoc_md459}
TLS supports authentication and encryption using a pre-\/shared key (i.\+e. a key that both client and server know) as an alternative to the public key cryptography commonly used on the web for HTTPS. PSK is starting to be used for MQTT, e.\+g. in mosquitto, to simplify the set-\/up and avoid having to go through the whole CA, cert, and private key process.

A pre-\/shared key is a binary string of up to 32 bytes and is commonly represented in hex form. In addition to the key, clients can also present an id and typically the server allows a different key to be associated with each client id. In effect this is very similar to username and password pairs, except that unlike a password the key is not directly transmitted to the server, thus a connection to a malicious server does not divulge the password. Plus the server is also authenticated to the client.

To use PSK\+:
\begin{DoxyItemize}
\item Generate a random hex string (generating an MD5 or SHA for some file is one way to do this)
\item Come up with a string id for your client and configure your server to accept the id/key pair
\item In \doxylink{class_network_client_secure}{Network\+Client\+Secure} use set\+Pre\+Shared\+Key (or the appropriate connect method) to set the id/key combo
\item When \doxylink{class_network_client_secure}{Network\+Client\+Secure} connects to the target server it uses the id/key combo to authenticate the server (it must prove that it has the key too), authenticate the client and then negotiate encryption for the connection
\end{DoxyItemize}

Please see the Network\+Client\+PSK example.\hypertarget{README.md_autotoc_md460}{}\doxysubsection{\texorpdfstring{Specifying the ALPN Protocol}{Specifying the ALPN Protocol}}\label{README.md_autotoc_md460}
Application-\/\+Layer Protocol Negotiation (ALPN) is a Transport Layer Security (TLS) extension that allows the application layer to negotiate which protocol should be performed over a secure connection in a manner that avoids additional round trips and which is independent of the application-\/layer protocols.

For example, this is used with AWS IoT Custom Authorizers where an MQTT client must set the ALPN protocol to {\ttfamily mqtt}\+:
