\doxysubsection{Detailed Description}
This folder contains automated and manual tests for esp-\/modem component. Beside these tests, some jobs are executed in CI to exercise standard examples (please refer to the CI definition and CI related sdkconfigs in examples).

List of test projects\+:


\begin{DoxyItemize}
\item {\ttfamily host\+\_\+test} -- esp\+\_\+modem is build on host (linux), modem\textquotesingle{}s terminal in mocked using Loobpack class which creates simple responders to AT and CMUX mode. This test is executed in CI.
\item {\ttfamily target} -- test executed on target with no modem device, just a pppd running on the test runner. This test is executed in CI.
\item {\ttfamily target\+\_\+ota} -- Manual test which perform OTA over PPP.
\item {\ttfamily target\+\_\+iperf} -- Manual test to measure data throughput via PPP.
\end{DoxyItemize}\hypertarget{README.md_autotoc_md1238}{}\doxysubsection{\texorpdfstring{Manual testing}{Manual testing}}\label{README.md_autotoc_md1238}
Prior to every {\ttfamily esp\+\_\+modem} release, these manual tests must be executed and pass (IDF-\/9074 to move the manual tests to CI)\hypertarget{README.md_autotoc_md1239}{}\doxysubsubsection{\texorpdfstring{{\ttfamily target\+\_\+ota}}{{\ttfamily target\+\_\+ota}}}\label{README.md_autotoc_md1239}
Make sure that the UART ISR is not in IRAM, so the error messages are expected in the log, but the ESP32 should recover and continue with downloading the image.

Perform the test for these devices
\begin{DoxyItemize}
\item SIM7600 (CMUX mode)
\item BG96 (CMUX mode)
\item SIM7000 (PPP mode)
\item A7672 (CMUX mode -- the only device with 2 byte CMUX payload), so the test is expected to fail more often if ({\ttfamily CONFIG\+\_\+\+ESP\+\_\+\+MODEM\+\_\+\+CMUX\+\_\+\+DEFRAGMENT\+\_\+\+PAYLOAD=y} \&\& {\ttfamily CONFIG\+\_\+\+ESP\+\_\+\+MODEM\+\_\+\+USE\+\_\+\+INFLATABLE\+\_\+\+BUFFER\+\_\+\+IF\+\_\+\+NEEDED=n} \&\& dte\+\_\+buffer \texorpdfstring{$<$}{<} device max payload)
\item Network\+DCE -- no modem device, pppd (PPP mode)
\end{DoxyItemize}

Perform the test with these configurations\+:
\begin{DoxyItemize}
\item CONFIG\+\_\+\+TEST\+\_\+\+USE\+\_\+\+VFS\+\_\+\+TERM (y/n)
\item CONFIG\+\_\+\+ESP\+\_\+\+HTTP\+\_\+\+CLIENT\+\_\+\+ENABLE\+\_\+\+CUSTOM\+\_\+\+TRANSPORT (y/n)
\item CONFIG\+\_\+\+ESP\+\_\+\+MODEM\+\_\+\+CMUX\+\_\+\+DEFRAGMENT\+\_\+\+PAYLOAD (y/n)
\item CONFIG\+\_\+\+ESP\+\_\+\+MODEM\+\_\+\+USE\+\_\+\+INFLATABLE\+\_\+\+BUFFER\+\_\+\+IF\+\_\+\+NEEDED (y/n)
\end{DoxyItemize}

{\bfseries{Criteria for passing the test}}

The test should complete the download with maximum 1 retry (50\% of OTA failure) In case of CMUX mode, we\textquotesingle{}re trying to exit CMUX at the end of the test. This step might also fail for some devices, as the CMUX-\/exit is not supported on certain devices (when the final error message appears that the device failed to exit CMUX, we just verify the new image by reseting the ESP32)\hypertarget{README.md_autotoc_md1240}{}\doxysubsubsection{\texorpdfstring{{\ttfamily target\+\_\+iperf}}{{\ttfamily target\+\_\+iperf}}}\label{README.md_autotoc_md1240}
Run these 4 {\ttfamily iperf} configurations (either manually or using {\ttfamily pytest})\+:
\begin{DoxyItemize}
\item tcp\+\_\+tx\+\_\+throughput
\item tcp\+\_\+rx\+\_\+throughput
\item udp\+\_\+tx\+\_\+throughput
\item udp\+\_\+rx\+\_\+throughput
\end{DoxyItemize}

And verify in all four cases the value is about 0.\+70 Mbps
