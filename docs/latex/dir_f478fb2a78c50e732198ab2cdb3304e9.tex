\doxysubsection{Detailed Description}
This example shows how to configure Zigbee Coordinator and use it as a Home Automation (HA) thermostat.

{\bfseries{This example is based on ESP-\/\+Zigbee-\/\+SDK example esp\+\_\+zigbee\+\_\+\+HA\+\_\+sample/\+HA\+\_\+thermostat.}}\hypertarget{README.md_autotoc_md808}{}\doxysubsection{\texorpdfstring{Supported Targets}{Supported Targets}}\label{README.md_autotoc_md808}
Currently, this example supports the following targets.

Note\+:
\begin{DoxyItemize}
\item This board means the board (e.\+g. ESP32-\/\+H2) loaded with {\ttfamily Zigbee\+\_\+\+Thermostat} example.
\item The remote board means the board (e.\+g. ESP32-\/\+H2) loaded with {\ttfamily Zigbee\+\_\+\+Temperature\+\_\+\+Sensor} example.
\end{DoxyItemize}

Functions\+:
\begin{DoxyItemize}
\item By clicking the button (BOOT) on this board, this board will read temperature value, temperature measurement range and temperature tolerance from the remote board. Also, this board will configure the remote board to report the measured temperature value every 10 seconds or every 2 degree changes.
\end{DoxyItemize}\hypertarget{README.md_autotoc_md810}{}\doxysubsubsection{\texorpdfstring{Hardware Required}{Hardware Required}}\label{README.md_autotoc_md810}

\begin{DoxyItemize}
\item One development board (ESP32-\/\+H2 or ESP32-\/\+C6) acting as Zigbee end device (loaded with Zigbee\+\_\+\+Temperature\+\_\+\+Sensor example).
\item A USB cable for power supply and programming.
\item Choose another board (ESP32-\/\+H2 or ESP32-\/\+C6) as Zigbee coordinator (loaded with Zigbee\+\_\+\+Thermostat example).
\end{DoxyItemize}\hypertarget{README.md_autotoc_md811}{}\doxysubsubsubsection{\texorpdfstring{Configure the Project}{Configure the Project}}\label{README.md_autotoc_md811}

If the End device flashed with the example {\ttfamily Zigbee\+\_\+\+Temperature\+\_\+\+Sensor} is not connecting to the coordinator, erase the flash of the End device before flashing the example to the board. It is recommended to do this if you re-\/flash the coordinator. You can do the following\+:


\begin{DoxyItemize}
\item In the Arduino IDE go to the Tools menu and set {\ttfamily Erase All Flash Before Sketch Upload} to {\ttfamily Enabled}.
\item In the {\ttfamily Zigbee\+\_\+\+Temperature\+\_\+\+Sensor} example sketch call {\ttfamily Zigbee.\+factory\+Reset();}.
\end{DoxyItemize}

By default, the coordinator network is closed after rebooting or flashing new firmware. To open the network you have 2 options\+:


\begin{DoxyItemize}
\item Open network after reboot by setting {\ttfamily Zigbee.\+set\+Reboot\+Open\+Network(time);} before calling {\ttfamily Zigbee.\+begin();}.
\item In application you can anytime call {\ttfamily Zigbee.\+open\+Network(time);} to open the network for devices to join.
\end{DoxyItemize}

{\itshape {\bfseries{Important\+: Make sure you are using a good quality USB cable and that you have a reliable power source}}}


\begin{DoxyItemize}
\item {\bfseries{LED not blinking\+:}} Check the wiring connection and the IO selection.
\item {\bfseries{Programming Fail\+:}} If the programming/flash procedure fails, try reducing the serial connection speed.
\item {\bfseries{COM port not detected\+:}} Check the USB cable and the USB to Serial driver installation.
\end{DoxyItemize}
