\doxysubsection{Detailed Description}
Group of functions used to parse CBOR streams. 

Tiny\+CBOR provides functions for pull-\/based stream parsing of a CBOR-\/encoded payload. The main data type for the parsing is a \doxylink{struct_cbor_value}{Cbor\+Value}, which behaves like an iterator and can be used to extract the encoded data. It is first initialized with a call to \doxylink{group___cbor_parsing_ga9016334cec2bfedef7eaa54da5144ea3}{cbor\+\_\+parser\+\_\+init()} and is usually used to extract exactly one item, most often an array or map.

Nested \doxylink{struct_cbor_value}{Cbor\+Value} objects can be parsed using \doxylink{group___cbor_parsing_ga0c8a61e484973272f34b00cfbef9ddfd}{cbor\+\_\+value\+\_\+enter\+\_\+container()}. Each call to \doxylink{group___cbor_parsing_ga0c8a61e484973272f34b00cfbef9ddfd}{cbor\+\_\+value\+\_\+enter\+\_\+container()} must be matched by a call to \doxylink{group___cbor_parsing_ga51e02f0b62bc864fe8cf290988936e15}{cbor\+\_\+value\+\_\+leave\+\_\+container()}, with the exact same parameters.

\doxysubsubsubsection*{Memory and parsing constraints}

Tiny\+CBOR is designed to run with little memory and with minimal overhead. Except where otherwise noted, the parser functions always run on constant time (O(1)), do not recurse and never allocate memory (thus, stack usage is bounded and is O(1)).

\doxysubsubsubsection*{Error handling and preconditions}

All functions operating on a \doxylink{struct_cbor_value}{Cbor\+Value} return a Cbor\+Error condition, with Cbor\+No\+Error standing for the normal situation in which no parsing error occurred. All functions may return parsing errors in case the stream cannot be decoded properly, be it due to corrupted data or due to reaching the end of the input buffer.

Error conditions must not be ignored. All decoder functions have undefined behavior if called after an error has been reported, and may crash.

Some functions are also documented to have preconditions, like \doxylink{group___cbor_parsing_ga4c2df69dc63dbf9f2851fbebbf7d2641}{cbor\+\_\+value\+\_\+get\+\_\+int()} requiring that the input be an integral value. Violation of preconditions also results in undefined behavior and the program may crash.

If the iterator {\itshape value} does not point to an integer value, the behavior is undefined, so checking with \doxylink{group___cbor_parsing_ga89c669eb345c1f6fa0c017e6a96d8fee}{cbor\+\_\+value\+\_\+get\+\_\+type} or with \doxylink{group___cbor_parsing_gab31913738c4470d6391d795143a97ab1}{cbor\+\_\+value\+\_\+is\+\_\+integer} is recommended.

This function is provided because CBOR negative integers can assume values that cannot be represented with normal 64-\/bit integer variables.

If the integer is unsigned (that is, if \doxylink{group___cbor_parsing_ga635f32e893b27ce99c63481ac60039ea}{cbor\+\_\+value\+\_\+is\+\_\+unsigned\+\_\+integer()} returns true), then {\itshape result} will contain the actual value. If the integer is negative, then {\itshape result} will contain the absolute value of that integer, minus one. That is, {\ttfamily \{actual} = -\/result -\/ 1\}. On architectures using two\textquotesingle{}s complement for representation of negative integers, it is equivalent to say that {\itshape result} will contain the bitwise negation of the actual value.

Cbor\+Error cbor\+\_\+value\+\_\+text\+\_\+string\+\_\+equals (\begin{DoxyParamCaption}\item[{const \mbox{\hyperlink{struct_cbor_value}{Cbor\+Value}} \texorpdfstring{$\ast$}{*}}]{value}{, }\item[{const char \texorpdfstring{$\ast$}{*}}]{string}{, }\item[{bool \texorpdfstring{$\ast$}{*}}]{result}{}\end{DoxyParamCaption})}

Compares the entry {\itshape value} with the string {\itshape string} and stores the result in {\itshape result}. If the value is different from {\itshape string} {\itshape result} will contain {\ttfamily false}.

The entry at {\itshape value} may be a tagged string. If {\itshape value} is not a string or a tagged string, the comparison result will be false.

CBOR requires text strings to be encoded in UTF-\/8, but this function does not validate either the strings in the stream or the string {\itshape string} to be matched. Moreover, comparison is done on strict codepoint comparison, without any Unicode normalization.

This function may not run in constant time (it will run in O(n) time on the number of chunks). It requires constant memory (O(1)).
