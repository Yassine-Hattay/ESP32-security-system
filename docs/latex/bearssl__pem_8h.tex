\doxysubsection{Detailed Description}
\hypertarget{bearssl__pem_8h_autotoc_md97}{}\doxysubsection{\texorpdfstring{PEM Support}{PEM Support}}\label{bearssl__pem_8h_autotoc_md97}
PEM is a traditional encoding layer use to store binary objects (in particular X.\+509 certificates, and private keys) in text files. While the acronym comes from an old, defunct standard ("{}\+Privacy Enhanced \+Mail"{}), the format has been reused, with some variations, by many systems, and is a {\itshape de facto} standard, even though it is not, actually, specified in all clarity anywhere.\hypertarget{bearssl__pem_8h_autotoc_md98}{}\doxysubsubsection{\texorpdfstring{Format Details}{Format Details}}\label{bearssl__pem_8h_autotoc_md98}
Bear\+SSL contains a generic, streamed PEM decoder, which handles the following format\+:


\begin{DoxyItemize}
\item The input source (a sequence of bytes) is assumed to be the encoding of a text file in an ASCII-\/compatible charset. This includes ISO-\/8859-\/1, Windows-\/1252, and UTF-\/8 encodings. Each line ends on a newline character (U+000A LINE FEED). The U+000D CARRIAGE RETURN characters are ignored, so the code accepts both Windows-\/style and Unix-\/style line endings.
\item Each object begins with a banner that occurs at the start of a line; the first banner characters are "{}\`{}-\/-\/-\/-\/-\/\+BEGIN \`{}"{} (five dashes, the word "{}\+BEGIN"{}, and a space). The banner matching is not case-\/sensitive.
\item The {\itshape object name} consists in the characters that follow the banner start sequence, up to the end of the line, but without trailing dashes (in "{}normal"{} PEM, there are five trailing dashes, but this implementation is not picky about these dashes). The Bear\+SSL decoder normalises the name characters to uppercase (for ASCII letters only) and accepts names up to 127 characters.
\item The object ends with a banner that again occurs at the start of a line, and starts with "{}\`{}-\/-\/-\/-\/-\/\+END \`{}"{} (again case-\/insensitive).
\item Between that start and end banner, only Base64 data shall occur. Base64 converts each sequence of three bytes into four characters; the four characters are ASCII letters, digits, "{}\`{}+\`{}"{} or "{}\`{}-\/\`{}"{} signs, and one or two "{}\`{}=\`{}"{} signs may occur in the last quartet. Whitespace is ignored (whitespace is any ASCII character of code 32 or less, so control characters are whitespace) and lines may have arbitrary length; the only restriction is that the four characters of a quartet must appear on the same line (no line break inside a quartet).
\item A single file may contain more than one PEM object. Bytes that occur between objects are ignored.
\end{DoxyItemize}\hypertarget{bearssl__pem_8h_autotoc_md99}{}\doxysubsubsection{\texorpdfstring{PEM Decoder API}{PEM Decoder API}}\label{bearssl__pem_8h_autotoc_md99}
The PEM decoder offers a state-\/machine API. The caller allocates a decoder context, then injects source bytes. Source bytes are pushed with {\ttfamily \doxylink{bearssl__pem_8h_a4d370a4ca904e4bcd0b90495821949ad}{br\+\_\+pem\+\_\+decoder\+\_\+push()}}. The decoder stops accepting bytes when it reaches an "{}event"{}, which is either the start of an object, the end of an object, or a decoding error within an object.

The {\ttfamily \doxylink{bearssl__pem_8h_a9e0c4331448f2a7496fbfc83484019a6}{br\+\_\+pem\+\_\+decoder\+\_\+event()}} function is used to obtain the current event; it also clears it, thus allowing the decoder to accept more bytes. When a object start event is raised, the decoder context offers the found object name (normalised to ASCII uppercase).

When an object is reached, the caller must set an appropriate callback function, which will receive (by chunks) the decoded object data.

Since the decoder context makes no dynamic allocation, it requires no explicit deallocation.

size\+\_\+t br\+\_\+pem\+\_\+encode (\begin{DoxyParamCaption}\item[{void \texorpdfstring{$\ast$}{*}}]{dest}{, }\item[{const void \texorpdfstring{$\ast$}{*}}]{data}{, }\item[{size\+\_\+t}]{len}{, }\item[{const char \texorpdfstring{$\ast$}{*}}]{banner}{, }\item[{unsigned}]{flags}{}\end{DoxyParamCaption})}



Encode an object in PEM. 

This function encodes the provided binary object ({\ttfamily data}, of length {\ttfamily len} bytes) into PEM. The {\ttfamily banner} text will be included in the header and footer (e.\+g. use {\ttfamily "{}\+CERTIFICATE"{}} to get a {\ttfamily "{}\+BEGIN CERTIFICATE"{}} header).

The length (in characters) of the PEM output is returned; that length does NOT include the terminating zero, that this function nevertheless adds. If using the returned value for allocation purposes, the allocated buffer size MUST be at least one byte larger than the returned size.

If {\ttfamily dest} is {\ttfamily NULL}, then the encoding does not happen; however, the length of the encoded object is still computed and returned.

The {\ttfamily data} pointer may be {\ttfamily NULL} only if {\ttfamily len} is zero (when encoding an object of length zero, which is not very useful), or when {\ttfamily dest} is {\ttfamily NULL} (in that case, source data bytes are ignored).

Some {\ttfamily flags} can be specified to alter the encoding behaviour\+:


\begin{DoxyItemize}
\item If {\ttfamily BR\+\_\+\+PEM\+\_\+\+LINE64} is set, then line-\/breaking will occur after every 64 characters of output, instead of the default of 76.
\item If {\ttfamily BR\+\_\+\+PEM\+\_\+\+CRLF} is set, then end-\/of-\/line sequence will use CR+\+LF instead of a single LF.
\end{DoxyItemize}

The {\ttfamily data} and {\ttfamily dest} buffers may overlap, in which case the source binary data is destroyed in the process. Note that the PEM-\/encoded output is always larger than the source binary.
