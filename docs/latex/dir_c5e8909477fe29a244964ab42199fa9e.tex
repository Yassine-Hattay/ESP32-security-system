\doxysubsection{Detailed Description}
\hypertarget{README.md_autotoc_md1214}{}\doxysubsection{\texorpdfstring{Overview}{Overview}}\label{README.md_autotoc_md1214}
This example is mainly targets experimenting with a modem device, sending custom commands and switching to PPP mode using esp-\/console, command line API. Please check the list of supported commands using {\ttfamily help} command.

This example implements two very simple network commands to demonstrate and test basic network functionality.
\begin{DoxyItemize}
\item {\ttfamily httpget}\+: Connect and get http content
\item {\ttfamily ping}\+: Send ICMP pings
\end{DoxyItemize}

To demonstrate creating custom modem devices, this example creates a DCE object using a locally defined create method, that sets up the DCE based on a custom module implemented in the {\ttfamily \doxylink{my__module__dce_8hpp_source}{my\+\_\+module\+\_\+dce.\+hpp}} file. The module class only overrides {\ttfamily get\+\_\+module\+\_\+name()} method supplying a user defined name, but keeps all other commands the same as defined in the {\ttfamily Generic\+Module} class.\hypertarget{README.md_autotoc_md1215}{}\doxysubsubsection{\texorpdfstring{USB DTE support}{USB DTE support}}\label{README.md_autotoc_md1215}
For USB enabled targets (ESP32-\/\+S2, ESP32-\/\+S3, or ESP32-\/\+P4), it is possible to connect to the modem device via USB.
\begin{DoxyEnumerate}
\item In menuconfig, navigate to {\ttfamily Example Configuration-\/\texorpdfstring{$>$}{>}Type of serial connection to the modem} and choose {\ttfamily USB}.
\item Connect the modem USB signals to your ESP chip (pin 19 (DATA-\/) and 20 (DATA+) for ESP32-\/\+S2/\+S3).
\end{DoxyEnumerate}

USB example uses Quactel BG96 modem device. BG96 needs a positive pulse on its PWK pin to boot-\/up.

This example supports USB modem hot-\/plugging and reconnection. There is one limitation coming from esp\+\_\+console component\+: When esp\+\_\+console REPL is being destroyed (after USB mode disconnection or after {\ttfamily exit} command), it will block on UART read. You must send a character to it (via idf.\+py monitor), so it unblocks and properly exits.
