Select algorithms and certificates for this connection. 

This callback function shall fill the provided {\ttfamily choices} structure with the policy choices for this connection. This entails selecting the cipher suite, hash function for signing the Server\+Key\+Exchange (applicable only to ECDHE cipher suites), and certificate chain to send.

The callback receives a pointer to the server context that contains the relevant data. In particular, the functions {\ttfamily br\+\_\+ssl\+\_\+server\+\_\+get\+\_\+client\+\_\+suites()}, {\ttfamily br\+\_\+ssl\+\_\+server\+\_\+get\+\_\+client\+\_\+hashes()} and {\ttfamily br\+\_\+ssl\+\_\+server\+\_\+get\+\_\+client\+\_\+curves()} can be used to obtain the cipher suites, hash functions and elliptic curves supported by both the client and server, respectively. The {\ttfamily br\+\_\+ssl\+\_\+engine\+\_\+get\+\_\+version()} and {\ttfamily br\+\_\+ssl\+\_\+engine\+\_\+get\+\_\+server\+\_\+name()} functions yield the protocol version and requested server name (SNI), respectively.

This function may modify its context structure ({\ttfamily pctx}) in arbitrary ways to keep track of its own choices.

This function shall return 1 if appropriate policy choices could be made, or 0 if this connection cannot be pursued.

Perform key exchange (server part). 

This callback is invoked to perform the server-\/side cryptographic operation for a key exchange that is not ECDHE. This callback uses the private key.

{\bfseries{For RSA key exchange}}, the provided {\ttfamily data} (of length {\ttfamily \texorpdfstring{$\ast$}{*}len} bytes) shall be decrypted with the server\textquotesingle{}s private key, and the 48-\/byte premaster secret copied back to the first 48 bytes of {\ttfamily data}.


\begin{DoxyItemize}
\item The caller makes sure that {\ttfamily \texorpdfstring{$\ast$}{*}len} is at least 59 bytes.
\item This callback MUST check that the provided length matches that of the key modulus; it shall report an error otherwise.
\item If the length matches that of the RSA key modulus, then processing MUST be constant-\/time, even if decryption fails, or the padding is incorrect, or the plaintext message length is not exactly 48 bytes.
\item This callback needs not check the two first bytes of the obtained pre-\/master secret (the caller will do that).
\item If an error is reported (0), then what the callback put in the first 48 bytes of {\ttfamily data} is unimportant (the caller will use random bytes instead).
\end{DoxyItemize}

{\bfseries{For ECDH key exchange}}, the provided {\ttfamily data} (of length {\ttfamily \texorpdfstring{$\ast$}{*}len} bytes) is the elliptic curve point from the client. The callback shall multiply it with its private key, and store the resulting X coordinate in {\ttfamily data}, starting at offset 0, and set {\ttfamily \texorpdfstring{$\ast$}{*}len} to the length of the X coordinate.


\begin{DoxyItemize}
\item If the input array does not have the proper length for an encoded curve point, then an error (0) shall be reported.
\item If the input array has the proper length, then processing MUST be constant-\/time, even if the data is not a valid encoded point.
\item This callback MUST check that the input point is valid.
\end{DoxyItemize}

Returned value is 1 on success, 0 on error.

Perform a signature (for a Server\+Key\+Exchange message). 

This callback function is invoked for ECDHE cipher suites. On input, the hash value or message to sign is in {\ttfamily data}, of size {\ttfamily hv\+\_\+len}; the involved hash function or algorithm is identified by {\ttfamily algo\+\_\+id}. The signature shall be computed and written back into {\ttfamily data}; the total size of that buffer is {\ttfamily len} bytes.

This callback shall verify that the signature length does not exceed {\ttfamily len} bytes, and abstain from writing the signature if it does not fit.

The {\ttfamily algo\+\_\+id} value matches that which was written in the {\ttfamily choices} structures by the {\ttfamily \doxylink{structbr__ssl__server__policy__class___abe8a7678839aa9ac7f905e2b404f7b88}{choose()}} callback. This will be one of the following\+:


\begin{DoxyItemize}
\item {\ttfamily 0x\+FF00 + id} for a hash function identifier {\ttfamily id}. In that case, the {\ttfamily data} buffer contains a hash value already computed over the data that is to be signed, of length {\ttfamily hv\+\_\+len}. The {\ttfamily id} may be 0 to designate the special MD5+\+SHA-\/1 concatenation (old-\/style RSA signing).
\item Another value, lower than {\ttfamily 0x\+FF00}. The {\ttfamily data} buffer then contains the raw, non-\/hashed data to be signed (concatenation of the client and server randoms and ECDH parameters). The callback is responsible to apply any relevant hashing as part of the signing process.
\end{DoxyItemize}

Returned value is the signature length (in bytes), or 0 on error.
