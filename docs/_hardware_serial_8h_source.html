223 // setRxTimeout sets the timeout after which onReceive callback will be called (after receiving data, it waits for this time of UART rx inactivity to call the callback fnc)
224 // param symbols_timeout defines a timeout threshold in uart symbol periods. Setting 0 symbol timeout disables the callback call by timeout.
225 // Maximum timeout setting is calculacted automatically by IDF. If set above the maximum, it is ignored and an error is printed on Serial0 (check console).
226 // Examples: Maximum for 11 bits symbol is 92 (SERIAL_8N2, SERIAL_8E1, SERIAL_8O1, etc), Maximum for 10 bits symbol is 101 (SERIAL_8N1).
227 // For example symbols_timeout=1 defines a timeout equal to transmission time of one symbol (~11 bit) on current baudrate.
228 // For a baudrate of 9600, SERIAL_8N1 (10 bit symbol) and symbols_timeout = 3, the timeout would be 3 / (9600 / 10) = 3.125 ms
229 bool setRxTimeout(uint8_t symbols_timeout);
230
231 // setRxFIFOFull(uint8_t fifoBytes) will set the number of bytes that will trigger UART_INTR_RXFIFO_FULL interrupt and fill up RxRingBuffer
232 // This affects some functions such as Serial::available() and Serial.read() because, in a UART flow of receiving data, Serial internal
233 // RxRingBuffer will be filled only after these number of bytes arrive or a RX Timeout happens.
234 // This parameter can be set to 1 in order to receive byte by byte, but it will also consume more CPU time as the ISR will be activates often.
235 bool setRxFIFOFull(uint8_t fifoBytes);
236
237 // onReceive will setup a callback that will be called whenever an UART interruption occurs (UART_INTR_RXFIFO_FULL or UART_INTR_RXFIFO_TOUT)
238 // UART_INTR_RXFIFO_FULL interrupt triggers at UART_FULL_THRESH_DEFAULT bytes received (defined as 120 bytes by default in IDF)
239 // UART_INTR_RXFIFO_TOUT interrupt triggers at UART_TOUT_THRESH_DEFAULT symbols passed without any reception (defined as 10 symbols by default in IDF)
240 // onlyOnTimeout parameter will define how onReceive will behave:
241 // Default: true -- The callback will only be called when RX Timeout happens.
242 // Whole stream of bytes will be ready for being read on the callback function at once.
243 // This option may lead to Rx Overflow depending on the Rx Buffer Size and number of bytes received in the streaming
244 // false -- The callback will be called when FIFO reaches 120 bytes and also on RX Timeout.
245 // The stream of incommig bytes will be "split" into blocks of 120 bytes on each callback.
246 // This option avoid any sort of Rx Overflow, but leaves the UART packet reassembling work to the Application.
247 void onReceive(OnReceiveCb function, bool onlyOnTimeout = false);
248
249 // onReceive will be called on error events (see hardwareSerial_error_t)
250 void onReceiveError(OnReceiveErrorCb function);
251
252 // eventQueueReset clears all events in the queue (the events that trigger onReceive and onReceiveError) - maybe useful in some use cases
253 void eventQueueReset();

312 // Enables or disables Hardware Flow Control using RTS and/or CTS pins (must use setAllPins() before)
313 // UART_HW_FLOWCTRL_DISABLE = 0x0 disable hardware flow control
314 // UART_HW_FLOWCTRL_RTS = 0x1 enable RX hardware flow control (rts)
315 // UART_HW_FLOWCTRL_CTS = 0x2 enable TX hardware flow control (cts)

322 // UART_MODE_RS485_COLLISION_DETECT = 0x03 mode: RS485 collision detection UART mode (used for test purposes)
